# Rules — verification-loop

1. Never claim pass/done/fixed without fresh command evidence in-session.
2. Discover and use this repo's real gate commands.
3. Fix failures; do not skip gates to declare victory.
4. Report failed test/check names explicitly — omission is a false report.
5. Subagent success is not evidence — re-verify.
6. Separate local gates from target-environment acceptance.
7. No harness-specific tool names.
