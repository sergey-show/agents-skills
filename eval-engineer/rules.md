# Rules — eval-engineer

1. Define evals before changing the system under test when doing EDD.
2. Never spend on full paid runs without dry-run + approved pilot.
3. Prefer deterministic graders; use humans sparingly.
4. Log failures as regression seeds — do not discard.
5. Do not move goalposts after seeing results without recording an amendment.
6. No vendor lock to a single eval SaaS — keep specs in-repo Markdown/JSON.
