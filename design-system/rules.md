# Rules — design-system

1. One source of truth — do not fork conflicting token files silently.
2. Every token needs a purpose statement.
3. Component rules must say when **not** to use the component.
4. Do not generate a second design system beside an existing one without a migration plan.
5. Lock palette, display face, and density with the user before mass rollout.
6. Ban lists must be explicit in DESIGN.md (Inter-as-display, AI purple, nested cards, emoji icons, invented metrics, etc.).
7. Dials are recorded, not vibes — later sessions read the numbers.
8. Prefer semantic colour names with hex, not only utility class dumps.
9. Motion section documents intent for implementers even when mockups are static.
10. Never invent brand assets or metrics into the system docs.
