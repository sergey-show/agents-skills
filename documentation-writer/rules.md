# Rules — documentation-writer

1. Verify commands and paths against the repo before publishing docs.
2. Do not invent features or flags that are not in code.
3. ADRs are append-only history; supersede instead of silently rewriting Accepted decisions.
4. Release notes claim only what landed; mark unknowns.
5. Prefer linking to code over duplicating large snippets that will rot.
6. No harness-specific tool names.
