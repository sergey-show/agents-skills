# Rules — interviewer

1. Do not write implementation/spec drafts until interview stop condition or user aborts to build.
2. Never ask for facts you can read from the repo/environment — look them up (or spawn fact-finder).
3. Mode A: one question at a time. Mode B: full frontier per round, then wait.
4. Always attach your best guess / recommendation so assumptions are visible.
5. Challenge "should want" answers; seek actual want.
6. Stop at confirmed shared understanding — don't endlessly grill for sport.
7. Non-interactive/CI: do not run this skill; raise underspecification as blocker.
8. No harness-specific tool names.
